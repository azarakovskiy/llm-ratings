# LLM Ratings — domain glossary

- **model** — a canonical AI model identity, anchored to an Artificial Analysis row: AA base slug as key (the API's UUID is per-effort-variant, not stable across a model's configurations), AA `name` as display name. Source strings (DeepSWE, Terminal-Bench) map onto it via an alias table.
- **provider** — the model's creator as listed by Artificial Analysis, not an API gateway or a pricing dimension.
- **provider selection** — a constraint on model creators: one named creator or all creators. It limits candidates and recommendation comparisons, not the reference sets of benchmark scores or relative grades.
- **provider picks** — the first and second distinct models for a creator under a role's active objective and eligibility rules, each at its objective-selected reasoning effort. Fewer than two eligible models yield fewer picks, not repeated efforts of one model or a fallback creator.
- **rating** — a published benchmark score for a model's measured reasoning effort and a particular source or source index. Artificial Analysis can supply distinct Intelligence, Coding and Agentic ratings for one configuration; source ratings remain separate, and Terminal-Bench agent×model results collapse to the best agent per (model × effort) for display.
- **index** — a named benchmark score within Artificial Analysis: Intelligence, Coding or Agentic. A role selects one index; an unavailable score is not replaced by another index.
- **configuration** — a model at one measured reasoning effort, carrying its distinct source/index ratings and available matching metrics.
- **reasoning effort** — the effort setting at which a configuration was measured, such as Low, Extra high or Maximum. Ratings and matching prices belong to that effort; a role's objective selects each model's effort rather than fixing one effort per role.
- **price** — Artificial Analysis's per-task cost for the Intelligence Index workload at a model's effort variant. It is a matching value, frontier and price-ranking basis for Intelligence only; no matching Coding/Agentic task cost is established. Token list prices are separate explanatory figures, not task costs.
- **frontier** — the Intelligence-based recommendation set: a (model × effort) configuration whose Intelligence Index no other configuration in the provider selection beats at equal-or-lower Intelligence task cost (Pareto upper envelope across efforts; all creators when unrestricted). Coding/Agentic advice has no cost frontier without a matching task-cost basis.
- **dominated** — an Intelligence configuration with a strict replacement in the provider selection: some other configuration has ≥ Intelligence score at ≤ Intelligence task cost, with one side strict. Same-effort replacements are preferred, with cross-effort fallback; this cost-based relation is unavailable for Coding/Agentic advice.
- **role** — a task-purpose stereotype used to choose a model. Cost, speed and thoroughness preferences, reasoning effort, context needs and capabilities such as vision are separate requirements or selection guidance, not role identities.
- **Explorer** — a role for finding and explaining existing code and repository behavior. It describes what exists rather than choosing an implementation approach.
- **Researcher** — a role for verifying external facts and producing sourced findings. It is distinct from local repository exploration.
- **Planner** — a role for choosing an approach and producing decisions and an actionable plan. It does not own implementation.
- **Coder** — a role for making and verifying changes, including fault diagnosis and implementation specialties such as UI design, tests and documentation.
- **Reviewer** — a role for independent assessment of changes or proposals, including security assessment and second-opinion critique. Implementing fixes is separate work.
- **Coordinator** — a role for dividing and delegating work, managing dependencies and combining results. It does not own each worker's implementation.
- **Generalist** — a role for mixed, end-to-end work when no specialist fits.
- **Utility** — a role for bounded auxiliary work such as titles, commit messages, classification and straightforward text transformations. Small output does not imply low capability needs; faithful summarization and memory extraction are not automatically trivial utility work.
- **objective** — the rule that selects one measured effort per model and orders models on the role's selected index: Highest capability, Best value or Lowest qualifying price. Intelligence supports all three; Coding/Agentic support Highest capability only, without price-based ties; timing is explanatory, not a selection rule.
- **Highest capability** — the objective that maximizes the published score on the role's selected Artificial Analysis index.
- **Best value** — the objective that maximizes Intelligence score per matching Intelligence benchmark task cost. This is a benchmark-value proxy, not a prediction of production-task return.
- **Lowest qualifying price** — the objective that minimizes matching Intelligence benchmark task cost among configurations meeting the role's capability floor.
- **alternative** — an Intelligence-based cheaper configuration within the provider selection, offered in the detail view: lower Intelligence task cost and an Intelligence Index within 5 points below the row's score, top 3, sorted by price. No cost-based alternatives are established for Coding/Agentic advice.
- **price tier** — a relative bucket of price, 1 = cheapest … 5 = most expensive, recomputed from the priced set on each refresh.
- **price-per-intelligence** — the Artificial Analysis Intelligence Index divided by its matching per-task cost at the configuration's reasoning effort; the value tier's raw number, one per row on that source-only basis. A missing, unusable or zero denominator does not provide a finite value ratio.
- **capability tier** — relative grade (1–5, 5 = best) within a score's reference population. Artificial Analysis grades use all scored configurations for the selected index across efforts in the refresh, independent of provider selection; other sources remain graded independently within each source's rated set at a given effort.
- **value tier** — relative grade (1–5, 5 = best) of Intelligence price-per-intelligence within a role's objective-selected model population before provider and capability-display constraints; a creator selection does not re-bin it.
- **speed tier** — relative grade (1–5, 5 = best) of Artificial Analysis median output tokens per second within a role's objective-selected model population before provider and capability-display constraints; it describes throughput, never selection or ties.
- **first-answer latency** — Artificial Analysis's published median time from request to first answer token, including thinking. It is distinct from time to first token, output throughput and estimated response time for 500 answer tokens; none is whole-agent task duration.
- **cost** — benchmark-run expenditure (DeepSWE's Modal cost, Terminal-Bench's per-run cost); a different basis from price, never mixed with it.
